Alta testnet · chain 63825 · approval-bound settlement

The approval becomes the chain's law.

A person approves one exact payroll batch. Ringfence compiles each line into a single-use mandate on Alta, signed on a separate device. A compromised Ringfence server can then pay only those lines, once each, before the approval expires.

1 · How it works

Two enforcers of the same rule.

On a bank rail, Ringfence's gate is the only thing between a compromised server and the money. On Alta there is a second one, in the transaction itself: the employer's account refuses any pull that the approved mandate does not allow.

The attacker is the Ringfence server itself: it holds every pull key and no owner key. Each attack runs twice, once against a broad mandate (what an agent wallet is usually given) and once against Ringfence's per-line mandates. Every cell is the chain's own answer.

5 · For agents

Read-only tools. No approve tool, no wallet field.

Connect any MCP client. The tools price a payroll, return the attack results and findings, return the signed certificate, and re-check the payroll against the chain. None can bind, sign, pull, revoke or approve, and none takes a wallet address or an amount.
